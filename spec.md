# Pantado — spec

Pantado is an AI-agent app for index trading on Avalanche. A user asks the agent, builds or picks an
index (a basket of tokenized stocks and crypto), and holds it as **one ERC-20 index token** bought in
one transaction. Anyone can create an index, public or private.

This file is the **what**. `STRUCTURE.md` is the **where**. Everything is built from scratch in this
repo.

---

## 1. Goal of this build

A contest build that is **mainnet-ready by configuration**.

| Plane | Runs on | Purpose |
|---|---|---|
| **Data plane** (display) | Avalanche **mainnet** (crypto) + Robinhood Chain **mainnet** (stock reference market) + a stock price API (cross-check) | Real prices, candles, pools, trades. Read-only. |
| **Execution plane** (swap, buy, sell, redeem, rebalance) | Avalanche **Fuji** (43113) | All transactions. Test tokens priced from the data plane. |

Switching execution to Avalanche mainnet is a **config change only** (`config/networks/*.json` +
`config/assets.json`), never a code change.

Target load: 2–5 concurrent users on one VPS. Service boundaries match the production target (§11)
so it scales by moving services, not rewriting them.

Out of scope for this build (roadmap only): contract audit, legal review, external LP capital for the
stock venue, multisig/timelock/KMS, a hook-based AMM pool for index tokens, real permissionless stock
pools on Avalanche.

## 2. Product surfaces

Reference UI: `apps/web/reference/pantado-app.html` (single file, open in a browser; every screen is
reachable by clicking). The app must match its layout, copy, type scale and brand. Data becomes real.
Screen list and behaviour notes: §12.

Navigation (left rail): **Ask · Swap · Marketplace · Create · Portfolio**. Top right: network pill
(Avalanche + "Fuji testnet" tag) and **Connect**. After connect the wallet button opens an account
menu: **Profile · Portfolio · Log out**.

- **Ask** — chat with the agent, modes **Auto** and **Deep**. Looks up assets, compares, explains,
  drafts an index ("Create from this" opens Create pre-filled).
- **Swap** — one swap card. Token pickers search by **ticker, name or contract address**, registry
  assets only. Buy/sell any stock or token against any other.
- **Marketplace** — one table of **public** indexes + stocks + tokens, chips All / Indexes / Stocks /
  Tokens, column "Data" shows the source of each row.
- **Asset page** — candlestick chart, Pools / Transactions tabs, buy/sell card.
- **Index page** — level chart, version banner (Manual) or plan status, tabs Composition /
  Transactions / Rebalances / Holders, agent assessment, **Buy / Sell only**.
- **Create** — Details, Basket, metrics, Rebalancing, visibility + first buy, Review step (§5.9).
- **Portfolio** — totals, creator earnings + claim, Index positions (Trade, **Redeem**), Your indexes
  (public and private, Open, New version for Manual), Wallet (donut by asset + asset table).
- **Redeem** — modal over Portfolio. Redeem lives **only** here.
- **New version** — propose new weights for a Manual index you own.
- **Profile** — creator page (handle, wallet, X link, public indexes).

Source badges: stocks show **"Reference market: Robinhood Chain (on-chain)"**; indexes show
**"Traded on Fuji testnet"** in the `contest` profile. Never state or imply that permissionless
stock pools on Avalanche are live. Pitch wording: "the stock venue is pluggable and will point to
permissionless stock pools on Avalanche once they are released".

## 5. Index core (contracts)

### 5.1 Concept
- An index is an ERC-20 (18 decimals) backed by a basket of **2–20** assets held in its own vault.
- Buy mints units, sell burns units, both **pro rata to the current basket**.
- **Redeem in-kind** returns the underlying assets: always open, no fee, needs no price, cannot be
  paused.
- Target weights are by value. Rebalancing moves the basket toward targets via public Dutch auctions.
- Auction prices never enter buy, sell or redeem.

### 5.2 Actors
creator (creates, chooses mode, earns the creator share) · holder (buys, sells, redeems) · filler
(anyone filling auctions) · keepers (price pusher, auction filler, rebalance trigger) · admin
(deployer EOA on testnet: registry params, oracle, venue caps, pause of new buys per asset).

### 5.3 Units
- Prices: USD per whole token, 1e18 fixed point. Quote: USDC (6 decimals; test USDC on Fuji).
- Weights: bps, sum 10 000, every weight ≥ 100 (1 %).
- **Index level starts at 100.00 USD per unit.**

### 5.4 Formulas
`B_i` vault balance, `p_i` price, `S` supply, `w_i` target weight, `f` trade fee.
- Basket value `V = Σ B_i·p_i`; level `L = V / S`; current weight `c_i = B_i·p_i / V`.

**Buy** with `u` USDC: `fee = u·f`, `u' = u − fee`; `spend_i = u'·c_i`; `q_i` = venue output;
`units = S · min_i(q_i / B_i)`; any excess over the min ratio stays in the vault (accrues to
holders); revert if `units < minUnits`.

**First buy** (`S = 0`): `spend_i = u'·w_i`; `units = Σ q_i·p_i / 100` (so `L = 100`). Also mint
**0.01 unit** (1 USD) to `0x…dEaD` so the index is never empty. Minimum first buy **100 USDC**.
Create and first buy happen in **one transaction** (§5.9).

**Sell** `s` units: `out_i = B_i·s / S`, each sold to USDC via its venue → gross `g`; pay
`g − g·f`; revert if below `minOut`.

**Redeem** `s` units: transfer `B_i·s / S` of every asset to `to`, no fee. `forfeit[]` lets the
holder skip assets the vault cannot transfer and redeem the rest.

**Stale price:** a price older than its `maxAgeSec` makes buy, sell and auctions revert. Redeem still
works.

### 5.5 Fees
- Trade fee `f` = **50 bps** on buy and sell, protocol-wide (not per creator). Split **30 bps
  protocol / 20 bps creator** (private indexes: creator share goes to protocol).
- Creation fee **5 USDC** flat to treasury.
- Creator earnings accrue in the fee splitter and are claimed by the creator.

### 5.6 Visibility
`public` | `private`, set at creation, can change **private → public** later (no fee). Public indexes
appear in the Marketplace and search immediately. Private indexes are listed only in their creator's
Portfolio; anyone with the address can still interact on-chain (the UI does not list them).

### 5.7 Rebalance modes
- **Off** — no trades; weights drift with prices.
- **Manual** — the creator publishes a **new version** (new target weights for the existing assets,
  every weight ≥ 1 %, with a reason). One plan at a time.
- **Auto** — targets are fixed; a plan starts when `max_i d_i ≥ θ` with
  `d_i = |c_i − w_i| / w_i` (**relative** drift), θ ∈ [10 %, 200 %] default 50 %, **or** every
  interval (default 30 days). Anyone may call the trigger once due.
- Mode changes take effect after 48 h. Auto → Manual must pass through Off.

### 5.8 Rebalance plan and auctions
- To move per asset: `T_i = (w_i − c_i)·V`; negative = overweight (sell), positive = buy.
- Overweight `i` is paired with underweight `j`; lots of `i` are auctioned for `j`.
- Dutch auction for a lot of `L` units of `i` paid in `j`: `ref = p_i / p_j`,
  `start = ref·(1 + 0.5 %)`, `floor = ref·(1 − 2 %)`, linear over **45 min**, never below floor.
  Partial fills allowed. Lot ≤ 1 % of `V`. A lot that mostly fails is retried at half size.
- Guards: public **notice 48 h** before start · ≤ **5 % of V traded per 24 h** · **loss budget 1 %
  of V** per plan (loss = Σ fair value given − fair value received), stop when reached · **max 14
  days**, filled trades stay, remainder dropped.
- Agent-managed indexes use the same Manual path and guards (§10.4).

### 5.9 Create flow
Inputs: name, **ticker (2–6 chars, A–Z/0–9, unique)**, description (optional, shown on the index
page), 2–20 assets, integer weights summing to 100 with each ≥ 1, mode (+ θ for Auto), visibility,
first buy ≥ 100 USDC. The app shows a **Review** step (basket, mode, first buy, creation fee, trade
fee, total, units received at level 100, "nothing is created if any purchase fails or a price is
stale"), then one signature calls `IndexFactory.createAndBuy`.

### 5.10 Contracts
`IndexFactory` (create + first buy, registry of indexes, ticker uniqueness, visibility), `IndexVault`
(ERC-20 units, buy/sell/redeem, holds the basket), `PriceOracle` (pushed prices with maxAge and
bands, optional Chainlink source), `FeeSplitter`, `Rebalancer` (modes, plans, auctions, guards),
`IndexLens` (read views: level, weights, drift, plan state), `IVenue` + venues (§6, §7),
`SwapRouter` (§7.1), test ERC-20s. Solidity 0.8.26, Foundry, OpenZeppelin 5.x.

## 6. Stock venue — `StockVenue` (synthetic, pluggable)

Implements `IVenue` (`quote(tokenIn, tokenOut, amountIn)`, `swapExactIn(tokenIn, tokenOut, amountIn,
minOut, to)`) for stocks. Stocks trade **24/7**; there are no market sessions.

- Holds a USDC **reserve** (contest: seeded by the deployer only).
- USDC → stock: USDC into the reserve, **mint** pToken to `to`. Stock → USDC: **burn**, pay USDC.
- Price: `PriceOracle` (stale → revert). Execution price `mid × (1 ± spreadBps)`, default **15 bps**.
- `quote` returns exactly what `swapExactIn` pays in the same block.
- Limits per asset (registry): `sizeCapUsd` per trade (Tier 1 25 000, Tier 2 5 000), `oiCapUsd`
  outstanding notional (Tier 1 250 000, Tier 2 50 000). Reserve guard: a buy reverts if
  `outstanding × reserveRatio > reserve` (default 150 %). Admin can pause **new buys** of one asset;
  sells stay open while the reserve allows. Redeem is a vault function and is never affected.
- Views: `reserve()`, `outstanding(asset)`, `exposureUsd(asset)`, `pnlUsd()`. Events: `Minted`,
  `Burned`, `CapsSet`, `BuysPaused`.
- Mainnet path (documented, not built): `production` can point stocks to a venue over real
  permissionless stock pools once released; `venue.production` selects it.

## 7. Token venues

- Contest: `TokenVenue` on Fuji — swaps test tokens at oracle price ± `spreadBps` from its own
  inventory, so Fuji fills match displayed mainnet prices.
- Production: `DexVenue` — swaps token↔USDC through a **registry-configured pool path** (Avalanche
  DEX pools) with caller `minOut`. Built and tested on an Avalanche mainnet **fork** only.

### 7.1 Single-asset swap
`SwapRouter` swaps any registry asset to any other through their venues (via USDC when needed), fee
**10 bps** to treasury. The Swap page token search accepts a contract address but only resolves
registry assets; anything else shows "No listed asset at this contract address".

## 8. Prices

One **canonical price per asset** feeds the app, quotes and Fuji.

| Kind | Canonical | Cross-check | On Fuji |
|---|---|---|---|
| Stock | Robinhood Chain reference pool mid, 60 s TWAP; if the pool has not traded within `referenceMaxAgeSec` (900 s), the stock API last trade | stock API | pushed |
| Token | Avalanche mainnet price engine (§9.3) | Chainlink where it exists | pushed |
| USDC | 1.00 | — | fixed |

If canonical and cross-check differ by more than `deviationBps` (200), the pusher does **not** push
and alerts; the on-chain price ages and goes stale by design. Push every 30 s or on a > 25 bps move.

## 9. Data layer

### 9.1 Ingestion
Ponder indexer (self-hosted), chains: `avalanche` (whitelisted pools + registry token transfers),
`robinhood` (reference pools of the 25 stocks), `fuji` (all Pantado contracts). Backfill 30 days on
mainnet chains, full history on Fuji. Accepted blocks only; writes idempotent on
`(chainId, blockNumber, txHash, logIndex)`.

### 9.2 Tables (Postgres + TimescaleDB)
`tokens`, `pools`, `swaps`, `transfers`, `balances`, `candles_1m` (+ 5m/1h/1d aggregates),
`indexes` (incl. visibility, description, mode), `index_events`, `index_levels` (per block),
`index_holders`, `plans`, `auctions`, `fills`, `venue_state`, `wallet_lots`, `creator_earnings`.

### 9.3 Price engine (tokens)
USDC = 1. WAVAX from the deepest WAVAX/USDC pool; others from their deepest pool vs USDC or WAVAX.
Ignore pools under $5 000 liquidity; drop outliers beyond 3σ of the last 20 swaps. Output to Redis
`price:<chain>:<id>` and the `prices` WS channel.

### 9.4 Derived data
- Board 24h per asset (price, 24h/7d/30d change, volume) — Marketplace.
- Index: level per block using canonical prices, **equal to `IndexLens` at the same block** (CI +
  monitor). Since-launch return, holders, volume, rebalance history, versions.
- Portfolio: index positions (value, PnL, drift), your indexes (incl. private), wallet assets with
  share of wallet, creator earnings. PnL by FIFO lots; unknown cost basis flagged.

### 9.5 Quotes
`POST /quote/basket` (buy/sell an index; per-leg venue, expected units or USDC, `minOut`),
`POST /quote/swap` (asset → asset through `SwapRouter`). Same math as the contracts (TS port,
golden-tested against forge fixtures). Quotes older than 2 blocks are refreshed before signing.

### 9.6 Presets (backend, deterministic, never the LLM)
Equal; Market cap (∝ market cap, 40 % cap, excess redistributed; cap rises to 100/n when n×40 <
100); Low volatility (∝ 1/σ of 90-day daily returns). Largest-remainder rounding to integers summing
to 100, each ≥ 1.

### 9.7 API
Fastify REST + WebSocket, hot responses cached 2–5 s in Redis.
`/assets`, `/assets/:id`, `/assets/:id/{candles,pools,trades}`, `/assets/search?q=` (ticker, name or
address; registry only), `/board?kind=`, `/indexes` (public only), `/indexes/:id`,
`/indexes/:id/{composition,transactions,rebalances,holders,levels}`, `/creators/:handle`,
`/portfolio/:address` (incl. private indexes of that address), `/presets`, `/quote/*`, `/health`.
WS: `prices`, `trades:<asset>`, `level:<index>`, `auctions`.

### 9.8 Targets
New trade visible ≤ 2 s after its block; `/quote/*` p50 ≤ 150 ms; displayed vs Fuji price gap ≤ 25
bps when fresh.

## 10. Agent

### 10.1 Harness
Provider-agnostic LLM client. Tools call the Pantado API only: `get_asset`, `compare_assets`,
`get_board`, `get_index`, `search_assets`, `get_presets`, `draft_index`, `explain`. Auto = fast
model, ≤ 4 steps; Deep = stronger model, ≤ 12 steps. SSE streaming. Chat history per wallet
(anonymous session before connect, 7-day expiry).

### 10.2 Draft index
One sentence → `{name, ticker, description, components[], weights[], preset, mode, rationale}`,
validated against the registry and §5 limits. "Create from this" opens Create pre-filled; the user
reviews and signs. The agent never signs user transactions.

### 10.3 Assessment
Per index: concentration, volatility, stock/token split, per-leg size caps, fee drag, rebalance
history. Built from data-layer numbers; regenerated on composition change.

### 10.4 Agent-managed indexes
Indexes labelled "Pantado Agent" are owned by a dedicated **agent-manager EOA** (testnet key). In
Manual mode it may publish new versions on its own indexes only, each with a rationale, through the
§5.8 guards. No other on-chain permission.

## 11. Infrastructure

### 11.1 Contest (built)
One VPS (≥ 4 vCPU, 16–24 GB RAM, 100 GB SSD), Docker Compose: `caddy`, `web` (Next.js
standalone), `api`, `market-data`, `indexer`, `agent`, `keepers` (price-pusher, auction-filler,
rebalance-trigger, auto-fund), `postgres` (TimescaleDB), `redis`, `prometheus` + `grafana`.
Cloudflare in front. Public RPC endpoints + ≥ 1 fallback each. Daily Postgres backup. A recorded demo
video is part of the deliverable.

### 11.2 Production (documented, not built)
Own AvalancheGo nodes on local NVMe, ClickHouse for swaps/transfers, Redpanda between ingestion and
consumers, Parquet cold storage, split hosts. Same service boundaries and config keys.

### 11.3 Monitoring
Indexer lag, price staleness per asset, canonical vs cross-check deviation, level(indexer) ≠
level(lens), auction loss vs budget, stock-venue reserve ratio and OI, keeper AVAX balances, API p95,
error rate.

## 12. App

Next.js (App Router, TypeScript), a port of `apps/web/reference/pantado-app.html`. Privy (Google, X,
email; embedded wallets) + external wallets. Gas sponsored for embedded wallets on Fuji. New embedded
wallets are **auto-funded once** with test USDC + AVAX by the `auto-fund` keeper on first sign-in (no
faucet screen). viem + `packages/sdk`.

Design rules: Inter for text, Inter Tight for titles and large numbers; type scale 11/12/13/14/15/
16/18/20/24/30 px; page titles 24 px; accent `#9052F9`; Avalanche red only for the network dot and
AVAX. Asset avatars: `logoURI` image, else two-letter avatar in the asset color. Index icon: the
split white/purple square. Long lists scroll inside their card (thin dark scrollbar).

Screens and notes:
- **Ask**, **Ask conversation** — agent cards for assets and draft indexes.
- **Swap** — single card; token picker with search (ticker, name, contract address).
- **Marketplace** — public indexes + assets, fixed column widths.
- **Asset** — chart, Pools (Pantado stock venue route + Robinhood reference pools) / Transactions,
  buy/sell card, max-per-trade error.
- **Index (public)** and **Index (private)** — private shows "Private · Only you", banner with **New
  version** and **Make public**.
- **Create**, **Review purchase**, **New version**.
- **Portfolio** — Index positions (Trade, Redeem), Your indexes (Open, New version), Wallet donut +

- States: loading, empty portfolio, stale price (buy/sell paused; redeem from Portfolio), per-trade

## 14. Acceptance (contest demo, `contest` profile)

1. One deploy script deploys all contracts to Fuji from config, registers 25 pTokens + test tokens,
   seeds the stock reserve, writes `contracts/deployments/fuji.json`.
2. Keepers live: every Fuji price within 25 bps of the displayed price.
3. Marketplace, asset pages and charts show live mainnet / Robinhood data with source badges.
4. Ask "make me an AI chips index with some BTC" → draft → Create pre-filled → Review → one signature
   (create + first buy) → index page shows level 100.00.
5. A second wallet buys, sells part, redeems part from Portfolio; level(indexer) == level(lens) after
   each step.
6. A stock buy above `sizeCapUsd` reverts with the UI message.
7. Price shock on one stock (scripted) → drift ≥ θ on an Auto index → auctions → filler fills →
   drift reduced within guards; Rebalances tab shows plan and fills.
8. Manual index: creator publishes a new version; it starts after 48 h notice (shortened in a demo
   config).
9. Private index: visible only in its creator's Portfolio; Make public → appears in Marketplace.
10. Stale price on one asset → buy/sell revert with UI message; redeem from Portfolio succeeds.
11. Monitoring green except the induced stale asset.

## 15. Glossary

**Level** — value of one index unit in USD (starts at 100). **pToken** — synthetic stock token minted
by the stock venue. **Canonical price** — the single price per asset used everywhere. **Reference
market** — the on-chain stock market on Robinhood Chain used for display and pricing. **Profile** —
`contest` or `production` network configuration.
